13  Tidy Data and Reshaping

In our introduction we have made reference to Tidy Data without really defining it. In this section, we will introduce the notion of tidy data, a tidyverse approach to dataframes, and reshaping dataframes between the long and wide representations.

13.1 Base R Dataframes

Working with large dataframes can be challenging if you inadvertently print all rows to the console. Consider the following example:

example_df <- data.frame(
  id = rep(paste0("id_", 1:500), each = 20),
  timepoint = rep(1:20, 500),
  disease_status = rep(
    sample(c("healthy", "diseased"), 20, replace = TRUE),
    each = 500
  ),
  blood_pressure = c(
    runif(20, 120, 140) |> round(),
    sample(c(NA, runif(19, 120, 140)), 9980, replace = TRUE)
  )
)
# Introduce a typo for demonstration
example_df[50, "disease_status"] <- "Healthy"

This dataframe contains 10,000 rows:

nrow(example_df)
[1] 10000

Printing the entire dataframe (e.g., simply typing example_df) would display all rows, which is both inconvenient and time-consuming. Instead, we typically use the head() function to preview just the first few rows:

head(example_df)
    id timepoint disease_status blood_pressure
1 id_1         1       diseased            129
2 id_1         2       diseased            121
3 id_1         3       diseased            130
4 id_1         4       diseased            127
5 id_1         5       diseased            130
6 id_1         6       diseased            129

However, constantly having to call head() is not ideal. A better solution is to convert the dataframe into a tibble.

13.2 Tidyverse DataFrames

Since tidyverse aims to provide a consistent interface for the entire data workflow, it is only natural that an alternative to the base R dataframe is available. The alternative, tibble, can be thought of a modern dataframe which is very similar to the base version, with slight tweaks. A tibble dataframe is:

  • Lazy: It does not do any implicit conversions like converting strings to factors unless you tell it to

  • Strict: It will not allow you to anything ambiguous.

Whilst saying that a dataframe is lazy and strict does not sound like a positive, this prevents unexpected behaviour which you can easily sink hours into debugging.

Another benefit of tibble is an improved visualisation interface. When you print a tibble, it only shows the first 10 rows and includes data type information for each column. This is particularly useful because it lets you quickly verify, for example, whether timepoint is numeric or character; information that can be obscured in the default dataframe printout. This display can help you catch issues like typos or unexpected data types early on.

library(tidyverse)

13.3 What is Tidy Data?

Tidy Data is defined a three strict rules. These rules define the structure of data, rather than allowing one’s stylistic views to define how data is structured. A dataset is tidy if:

  1. Each variable has its own column
  2. Each observation has its own row
  3. Each value lives in a single cell

Consistent data structure simplifies analysis, leverages vectorized operations, and makes it easier to use tidyverse functions.

13.4 Reshaping

Consider the following data. Is it tidy?

# A classic "Wide" dataset
scores_wide <- tibble(
  Student = c("Alice", "Bob", "Charlie"),
  Math    = c(88, 72, 95),
  English = c(90, 85, 80),
  History = c(75, 88, 92)
)

print(scores_wide)
# A tibble: 3 × 4
  Student  Math English History
  <chr>   <dbl>   <dbl>   <dbl>
1 Alice      88      90      75
2 Bob        72      85      88
3 Charlie    95      80      92

Recording data like this is very common in Excel and is a format we are familiar with. But what are the variables?

Converting the data to tidy data often improves how we can analyse (filter, group, summarise, plot) the data. We call this data long data, and the above Excel style data wide data. We can convert to long data with pivot_longer() from the tidyr package.

scores_long <- scores_wide %>%
  pivot_longer(
    cols = c(Math, English, History), # The columns we want to bundle up
    names_to = "Subject",             # What should we call the new key column?
    values_to = "Score"               # What should we call the new value column?
  )

print(scores_long)
# A tibble: 9 × 3
  Student Subject Score
  <chr>   <chr>   <dbl>
1 Alice   Math       88
2 Alice   English    90
3 Alice   History    75
4 Bob     Math       72
5 Bob     English    85
6 Bob     History    88
7 Charlie Math       95
8 Charlie English    80
9 Charlie History    92

In this long format, every row is a single test result or a single observation. We can easily summarise the data now; for example:

scores_long %>% 
  group_by(Student) %>% 
  summarise(Mean =  mean(Score))
# A tibble: 3 × 2
  Student  Mean
  <chr>   <dbl>
1 Alice    84.3
2 Bob      81.7
3 Charlie  89  
scores_long %>% 
  group_by(Subject) %>% 
  summarise(Mean =  mean(Score))
# A tibble: 3 × 2
  Subject  Mean
  <chr>   <dbl>
1 English    85
2 History    85
3 Math       85

If we want to return to the wide version of the data, for example if we have finished the analysis and want to create a table OR we want to cover calculations based on the difference between two subjects (this will be easier when the columns are still side-by-side), then we use pivot_wider().

# Let's turn our long data back into a human-readable table
report_table <- scores_long %>%
  pivot_wider(
    names_from = Subject,  # Which column holds the new column headers?
    values_from = Score    # Which column holds the values to fill the cells?
  )

print(report_table)
# A tibble: 3 × 4
  Student  Math English History
  <chr>   <dbl>   <dbl>   <dbl>
1 Alice      88      90      75
2 Bob        72      85      88
3 Charlie    95      80      92

13.5 Joining dataframes

The dplyr package also provides functions for joining dataframes, such as left_join() and inner_join().

The full-length notes are in the R4DS chapter on joins.

13.5.1 Key Joining Concepts in dplyr

Data analysis typically involves combining multiple data frames. Joins let you connect tables using shared keys, which can be primary keys (unique identifiers in one table) and foreign keys (variables that reference primary keys in another).

13.5.2 Summary

Again, here is a concise summary of the R4DS content on the joins section. More examples are available in the help files for each function (e.g. ?left_join).

13.5.2.2 Filtering Joins

Filtering joins select rows from one table based solely on whether they have a match in another table.

  • semi_join(): Keeps rows in x that have at least one match in y (does not add columns from y).

    # Keep only origin airports that appear in flights2
airports |> semi_join(flights2, join_by(faa == origin))
    # A tibble: 3 × 8
  faa   name                  lat   lon   alt    tz dst   tzone           
  <chr> <chr>               <dbl> <dbl> <dbl> <dbl> <chr> <chr>           
1 EWR   Newark Liberty Intl  40.7 -74.2    18    -5 A     America/New_York
2 JFK   John F Kennedy Intl  40.6 -73.8    13    -5 A     America/New_York
3 LGA   La Guardia           40.8 -73.9    22    -5 A     America/New_York

  • anti_join(): Keeps rows in x that have no match in y.

    # Find tail numbers in flights2 that are missing from planes
flights2 |> anti_join(planes, join_by(tailnum)) |> distinct(tailnum)

These joining functions provide a powerful and flexible way to integrate data from different sources, ensuring that your analyses are both comprehensive and accurate.

13.6 TL;DR

  1. Tibbles are strict, lazy data frames that print nicely and prevent silent errors.

  2. Wide Data is good for humans (spreadsheets). Long Data is good for computers (R).

  3. Use pivot_longer() to bundle multiple columns into two key columns (e.g., Subject and Score).

  4. Use pivot_wider() to spread two columns back out into a table.
